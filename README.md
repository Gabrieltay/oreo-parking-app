# Singapore Commercial Parking Cost Finder

Enter a Singapore location and a parking duration — get commercial carparks
within a radius (default 500m), ranked by **total cost for that exact
duration**, cheapest first.

Single Next.js app (frontend + API routes). No database — carpark data is a
static JSON file (`data/carparks.json`) generated by an offline build
pipeline and committed to the repo.

## Stack

- Next.js 16 (App Router) + TypeScript + Tailwind CSS
- Static `data/carparks.json`, loaded in-memory by the API route
- [OneMap Singapore](https://www.onemap.gov.sg/apidocs/) for geocoding
- Haversine distance, computed in code
- Anthropic API used only in the offline build pipeline (`scripts/`) to parse
  LTA's free-text rate strings into structured JSON — never called at
  request time

## Running the app

```bash
npm install
npm run dev
```

Open http://localhost:3000.

## Data pipeline

`data/carparks.json` is generated once and refreshed periodically by
re-running:

```bash
npm run build:data
```

which runs, in order:

1. `scripts/01-crawl.ts` — fetches LTA OneMotoring's 7 parking-rates pages
   and parses each HTML table into `data/raw-rates.json`.
2. `scripts/02-extract-rates.ts` — calls the Anthropic API (requires
   `ANTHROPIC_API_KEY`) to convert each row's free-text rate strings into
   structured `RatePeriod`/`CarparkRates` JSON (`data/parsed-rates.json`).
   Ambiguous rows are marked `{ type: "unparsed" }` and logged to
   `data/needs-review.json` rather than guessed.
3. `scripts/03-geocode.ts` — geocodes each carpark name via OneMap and
   writes the final `data/carparks.json` — the only file the running app
   reads.

Individual steps can also be run on their own: `npm run crawl`,
`npm run extract-rates`, `npm run geocode`.

**Note on the committed `data/carparks.json`:** this was built in a sandboxed
environment without egress to `onemotoring.lta.gov.sg` or
`www.onemap.gov.sg`, so it currently ships with a hand-authored sample of
~11 real, well-known Singapore commercial carparks (illustrative but
plausible rate structures, real coordinates) instead of a live crawl. Run
`npm run build:data` with real network access and an `ANTHROPIC_API_KEY` to
replace it with the full live dataset.

Singapore public holidays (used to resolve the Sunday/PH rate schedule) are
hardcoded in `lib/publicHolidays.ts` for 2025–2026; refresh against the
official data.gov.sg "Public Holidays" dataset when adding new years.

## Cost engine

`lib/costEngine.ts` is pure, unit-tested TypeScript (`npm test`) that:

- Resolves weekday/Saturday/Sunday-PH schedule per calendar day spanned by
  the parking interval (public holidays override the weekday/Saturday
  schedule).
- Splits the interval into segments wherever a rate-period boundary or
  calendar-day boundary falls, including periods that cross midnight.
- Prices each segment: `tiered` (first block + ceil'd subsequent blocks,
  optional cap), `flatEntry` (charged once per entry, not per window
  touched), `perMinute` (optional cap), or `unparsed` (excluded from cost,
  flagged for manual verification).
- Applies any day/time-window surcharges that overlap the interval.

## API

`POST /api/search`

```json
{ "address": "Suntec City", "startTime": "2026-07-07T15:10", "endTime": "2026-07-07T21:20", "radiusMeters": 500 }
```

Returns candidate carparks within `radiusMeters` (Haversine distance from
the geocoded address), sorted by total cost ascending, each with a
segment-by-segment breakdown. Carparks with any unparsed rate segment are
still returned (sorted after priced results) with `hasUnparsed: true`, shown
in the UI with a "verify on-site" badge.

`GET /api/geocode?q=<query>` proxies OneMap's search-as-you-type for the
address autocomplete field.
